## The common part (all the engines with a settings screen)

- **engine-specs `^0.4.1` → `^0.6.0`**. The app imports the helpers from `../engine-specs.js`, the
  runtime copy the Makefile already ships beside the SDK.
- **English and Spanish**:
  - every string of the app (today Spanish, inline) moves into one `{ en, es }` table;
  - the table is read through `host.locale ?? resolveLocale()`;
  - SDK errors stay English and are shown as a detail under the app's own words.
- **Pause menu**: Continuar, the engine's entries, **Ajustes**, **Pantalla completa**, Volver al
  lanzador (UX.md rule 4).
- **Ajustes**: `createSettingsScreen()`.
  - Rows come from `settingsModel()` over the SDK's `config()` / `options()` descriptors (only those
    with a `label`), plus `SHARED_SETTINGS`.
  - A live change is applied at once.
  - A non-live one is saved and passed at the next start; its row says "Se aplica al reiniciar".
  - Choices are saved per engine with `saveSettings('jgenesis')` and read at mount with
    `loadSettings()`.
- **Fullscreen**: `createFullscreenToggle(root)` (Cmd+Enter / Alt+Enter, Select + Y), plus the
  pause-menu entry.
- **Performance**:
  - `createWakeLock()`, held while playing when "Mantener la pantalla encendida" is on (default
    on);
  - `createPerfCounter()` when "Mostrar rendimiento" is on: fed once per emulated frame where the
    SDK reports frames, else counting display frames.
- **Controls and audio pacing**: per engine, below.
- **Checks**:
  - `make test` / build;
  - in Chromium, with the owner's test ROMs where needed: the pause menu, every setting applied (or
    noted as on restart), saved across a reload, fullscreen by key and by menu, the counter, en / es;
  - a phone width.
- **Release**: minor.

## jgenesis

- **Settings**: the 26 options in `src/jgenesis.options.ts`, all live through `WebConfigRef`
  (filtering, blending shader, prescaling, aspect per system, region, sprite limits, low-pass…).
  - Per-system rows only when that system is running (`engineConfig.supports`).
  - They become `label` / `group` / `valueLabels` with Spanish added.
- **Controls**: partial.
  - jgenesis-web reads the keyboard only. The SDK turns the gamepad into key events through its
    table (`jgenesis.sdk.ts`: per system, button → `KeyboardEvent.code`).
  - Remapping the **gamepad** is changing that table: feasible.
  - Remapping the **keyboard** depends on jgenesis-web's own input config: to check. If it cannot be
    set from outside, keys stay fixed and the Controls rows show them read-only.
- **Audio pacing**: not offered. The emulator runs its own loop inside the WASM (WebGPU).
- **Order**: third.

## Walkthrough (2026-11-17 21:30 UTC) — jgenesis done

Adds: what was built, what changed from the plan, and the checks. It is mGBA's template
(mGBA-wasm, same record), adapted.

**Changed from the plan**: **the keyboard is remapped too**, not only the gamepad. jgenesis-web
reads physical keys, and the SDK already sends it synthetic key events for the pad. So the SDK
now:
- catches a remapped physical key first (window, capture phase, real presses only) and sends
  jgenesis that control's own default key;
- swallows a default key no control has any more.

**SDK** (`src/`):
- `jgenesis.sdk.ts`:
  - `JGENESIS_CONTROLS`: each system's controls (Mega Drive A B C X Y Z Mode Start; Master System /
    Game Gear 1 2 Start; SNES; GBA; plus the d-pad), with their default key and pad button.
  - `controlTables()` turns bindings into the pad table, the key translation and the swallowed
    defaults; `padKeys()` takes the table.
  - `play.setControls({ keys, buttons })`, live.
  - `JGENESIS_OPTION_SYSTEM` re-exported.
- `jgenesis.options.ts`:
  - every option gets `label` / `group` / `valueLabels` (a section, its Spanish name and its
    values' Spanish). The two regions, which the spec redefines after the catalog, get them too;
  - `JGENESIS_OPTION_SYSTEM` says which system each option belongs to.

**App**: derived from mGBA's finished app, with these differences:
- Ajustes shows the general options and the running system's only.
- Controles lists the running system's controls, saved as `<system>.<control>`, so each console
  keeps its own.
- The counter counts display frames: jgenesis runs its own loop and reports none.
- The host's console hints and `escMenu: false` are kept.

**Checks**:
- `tsc` clean. `make test`: 6 tests, one new: remapped keys, swallowed defaults, the pad table, a
  swap that swallows nothing.
- In Chromium, with the published package's runtime and a homebrew Mega Drive ROM. Headless
  Chromium has no WebGPU, so there is no picture; the app, menus and settings run.
  - Ajustes: Vídeo (Suavizado, shader, prescaling, aspect, borders…), Audio (low-pass), Emulación
    (Región "Se aplica al reiniciar", CPU speed, sprite limit), and the Mega Drive's controls.
  - A takes K, then B takes K and A gets S (swap).
  - The counter shows 60 fps; Alt+Enter enters fullscreen.
  - After a reload the choices are back.
  - English at 390px.
- Not checked in a browser: keys reaching the emulator (no WebGPU here). The tables are covered by
  the test.
