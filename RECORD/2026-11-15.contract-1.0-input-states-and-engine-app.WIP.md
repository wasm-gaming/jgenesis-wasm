# Contract 1.0, gamepads, save states and the engine app

2026-11-15 14:13 · owner: "Habría que añadirlo a jgenesis y a snes9x" — the engine app blastem-wasm and fbneo-wasm
now have (suspend points, save states in the pause menu, menus by touch) and the touch pad. First
record of this repo (the org's records live in `RECORD/`).

**Status:** proposal — awaiting the owner's approval.

## Where jgenesis-wasm stands (0.1.1)

- Legacy contract: `load(config)`, engine-specs `^0.2.4` (ROADMAP: ❌ 1.0).
- Upstream's web frontend (`frontend/jgenesis-web`, Rust + winit + wgpu), patched by
  `scripts/patch-jgenesis-web.mjs` (open a ROM from bytes). Measured on upstream `master`:
  - **no save states** on the web: `save_state` / `load_state` exist only in the native driver
    (`jgenesis-native-driver`); the web keeps cartridge saves (SRAM) in IndexedDB;
  - **no gamepads** on the web: input is winit's keyboard only, so neither a physical pad nor the
    touch pad reaches it today;
  - rendering needs **WebGPU** (in headless Chromium the software adapter panics in
    `createBuffer(mappedAtCreation)` — seen in play.germade's Mega Drive record), so this
    session cannot see it run; a real device can.

## Plan

1. **Contract 1.0** — `JgenesisSDK` / `JgenesisPlay` on engine-specs' bases, self-contained ESM,
   storage under `jgenesis/<namespace>/`; `load()` goes (minor release).
2. **Gamepads, without touching Rust** — the SDK reads `navigator.getGamepads()` each frame and
   presses jgenesis' own key bindings for each system (Genesis A B C X Y Z Mode Start; SNES;
   Game Boy…) with `KeyboardEvent`s on the element winit listens to. Physical pads and the touch
   pad then both play.
3. **Save states — a Rust patch** in `patch-jgenesis-web.mjs`: two commands on the emulator
   channel, `request_save_state()` → the emulator's bincode bytes handed to JS, and
   `request_load_state(bytes)` (the core types are already `Encode + Decode`, as the native
   driver's slots show). The SDK stores them as slots in OPFS with blastem's `play.states` shape
   and a canvas snapshot. Needs a rebuild of the wasm (the build image).
4. **The engine app** — blastem's app on this SDK (`jgn-` classes); its Escape settings overlay
   off through the app.
5. **Verify** — `make test`; the patch applies and builds; the app's menus in Chromium; the game,
   the pads and the states on a device with WebGPU (the owner's).

## Order

Recommended: snes9x-wasm first (TypeScript only, verifiable here — its record is the same day),

## Walkthrough (2026-11-15 17:29 UTC) — what was done

**Upstream pinned.** The build cloned jgenesis' moving master; the patch no longer applied (and
the release before it, 0d858db, did not build for the web). `scripts/build-jgenesis.sh` now pins
`JGENESIS_REV=237545e` (master, 2026-11-14) with a shallow-since clone. The region patch was
re-anchored: Genesis regions are now `GenesisRegion::{NtscUs, NtscJp, Pal}`, mapped to/from the
SDK's `americas | japan | europe`.

**1. Contract 1.0.** `JgenesisSDK` / `JgenesisPlay` on engine-specs' bases (`load()`,
the manifest, `emit-manifest.mjs`, `demo.ts`, the theme and `tsconfig.demo.json` are gone).
`JGENESIS_SPEC` in `jgenesis.options.ts` holds every default; `romFileName` has none on
purpose — a default file name overrode the `console` hint (an SNES ROM ran as a Mega Drive one).
Storage under OPFS `jgenesis/<namespace>/`. `engine-specs.js` ships beside the SDK
(`scripts/localize-specs.mjs`). Version 0.2.0 (breaking).

**2. Gamepads via keys.** A rAF loop reads `navigator.getGamepads()` and dispatches
`KeyboardEvent`s (by `code`) on the canvas with upstream's default bindings per system
(Genesis, SNES, SMS/GG, GBA — checked against upstream `config.rs`); keys are released on pause.
Needed one fix in engine-specs: the touch pad hid itself on *any* keydown, so the SDK's own
synthetic keys hid the pad after the first press. engine-specs now ignores untrusted keydowns
(`RECORD/2026-11-15.virtual-touch-gamepad.WIP.md` there).

**3. Save states (Rust patch).** `EmulatorCommand::{SaveState, LoadState, Pause}`; on the
channel, `request_save_state` / `take_saved_state` / `request_load_state` /
`take_load_result` / `set_paused` / `is_paused` — in the `#[wasm_bindgen]` impl (a first
version put them in the plain impl, where JS cannot see them). The loop encodes with
`bincode::encode_to_vec(to_save_state())`, decodes and `load_state`s; while paused it drains
commands, suspends audio and waits 16 ms per tick. The SDK polls `take_saved_state` every 16 ms
(≤ 3 s) and keeps blastem's `play.states` shape (slots 0–3 + 9, `.state`/`.png`/`.lock`).

**Snapshot.** A WebGPU canvas drops its picture once presented, so `drawImage` outside the frame
read black (black slot thumbnails). `snapshot()` now copies the canvas in a microtask right
after the next `GPUQueue.submit()` (the prototype is wrapped once; it does nothing unless a
snapshot waits); while paused, the last copy stands in.

**Layout.** winit gives its canvas a device-pixel size and no CSS size, so it overflowed the
mount (878×672 on a 390-wide phone). The mount now caps it (`max-width/height: 100%`,
`object-fit: contain`).

**4. The engine app** — blastem's app (`jgn-` classes), `escMenu: false` through the app.

**5. Verified**
- `make test`: 5 / 5.
- Patch applied to 237545e and built locally (`cargo +nightly`, `wasm32-unknown-unknown`,
  `wasm-bindgen --target web`), single-thread glue.
- End to end in Chromium (iPhone 13 emulation, WebGPU on SwiftShader, headed under Xvfb — the
  headless compositor shows WebGPU pages black), with a test SNES ROM that paints the backdrop
  from JOY1: touch Y → blue frame (pad → gamepad → keys → game); the pad stays visible; the pause
  button opens the menu; slot 1 saved (`slot_0.state` 1.29 MB + `slot_0.png` in OPFS
  `jgenesis/jpadtest/`), thumbnail is the live frame; the slot sheet (Cargar / Guardar aquí /
  Bloquear / Borrar) and Cargar return to the game.
- Not verified here: the Docker build (`make build-wasm`) and the threaded build; a real device.
